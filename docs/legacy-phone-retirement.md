# Legacy phone login retirement

The old phone-login function used an editable profile phone to select a user, allowed reused OTPs with caller-controlled development origins, and replaced Auth passwords to create sessions. The replacement has no database/network access and returns HTTP 410 for POST, including forged origins, malformed bodies and test numbers. It never emits a token. Email/password login remains in the UI; phone controls now explain recovery.

Staging branch vxeydrzuvhouvjnttvgs was deployed and tested: POST with Origin localhost returns 410 and legacy_phone_login_retired. Local boundary tests and frontend build pass. Production deployment was rejected by automatic approval review because disabling this path could lock out existing users before a recovery plan is validated. Production remains unchanged.

Aggregate audit: 121 Auth accounts, zero native phone confirmations, two synthetic-email phone-only accounts. No user identifiers or credentials are in this document. Before production rollout, an authorized operator must privately identify those two accounts, validate control using an independent recovery procedure, attach a verified recovery email or native confirmed phone to each existing UUID, and test login. Do not assign a number from profiles, reset passwords through an OTP bridge, create duplicate accounts or bypass proof of possession. Keep an incident record and confirm other account data is unchanged. Existing sessions also need review; retiring this endpoint alone does not invalidate previously issued sessions.

The retired function must never be restored as a recovery mechanism. Native phone login can be introduced only after Auth provider configuration and explicit same-UUID phone enrollment with Auth OTP confirmation. The separate account-phone possession evidence does not automatically populate Auth.phone_confirmed_at.

`python scripts/provision-link-staging.py --help` describes a secret provisioning helper. It validates two healthy non-default branches, refuses production and existing linking secrets, reads the restricted SMS key without echo, creates a new 256-bit partner key and independent OTP peppers, uploads temporary mode-0600 env files, and deletes them. It leaves ACCOUNT_LINK_V1_ENABLED=false. This script has not been run against hosted secrets: the current connector has no secrets API and no authenticated CLI credential is available. An interrupted two-project write requires reconciliation before retrying; it is not atomic.
